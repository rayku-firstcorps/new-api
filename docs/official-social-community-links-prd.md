# 主页新增官方社群入口配置 PRD

## 1. 需求背景

当前前端主页已有“前往仪表盘”主按钮，但缺少官方社群和社交媒体入口。运营侧希望在主页为用户提供官方 Telegram、WhatsApp、Facebook、Instagram、X、VK 等社群或社交平台入口，用于公告触达、活动运营、用户支持和品牌信任建设。

本需求将原“加入 WhatsApp 官方社群”单按钮方案升级为“多个官方社群入口配置”方案。管理员可在后台配置多个社群入口，每个入口独立控制是否开启、展示名称、平台类型和跳转链接。

## 2. 需求目标

- 在前端主页“前往仪表盘”按钮旁新增官方社群入口区域。
- 支持配置多个官方社群或社交平台入口。
- 后台支持为每个平台独立配置是否开启和跳转链接。
- 前端仅展示已开启且链接合法的入口。
- 支持常见平台：Telegram、WhatsApp、Facebook、Instagram、X、VK，并保留后续扩展能力。
- 新增前端文案接入 i18n，避免硬编码多语言文案。

## 3. 需求范围

### 3.1 本期范围

- 默认前端主页新增官方社群入口展示逻辑。
- 后台系统设置页新增“官方社群入口”配置模块。
- 支持多个平台入口的新增、编辑、启用、停用、排序和删除。
- 支持平台类型、展示名称、链接、启用状态配置。
- 前后端配置读取、保存和校验。
- 入口文案和后台配置文案的前端国际化。
- 桌面端和移动端布局适配。

### 3.2 非本期范围

- 不集成第三方平台 API。
- 不做社群成员统计、点击追踪、邀请追踪或转化分析。
- 不自动校验社群链接是否真实可访问。
- 不支持用户按地区、语言或分组看到不同社群入口。
- 不改造现有“前往仪表盘”按钮逻辑。

## 4. 目标用户与场景

| 用户 | 核心诉求 | 使用场景 |
| --- | --- | --- |
| 普通用户 | 快速找到官方社群入口 | 用户访问主页时，点击 Telegram、WhatsApp 等入口加入官方社群 |
| 管理员 | 灵活管理多个官方入口 | 管理员根据运营策略开启、关闭、排序或更新不同平台链接 |
| 运营人员 | 提升用户触达和社群转化 | 通过多个社群渠道发布公告、活动和支持信息 |

## 5. 功能需求

### 5.1 主页入口展示

在前端主页“前往仪表盘”按钮旁新增官方社群入口。

展示形式建议：

- 当仅配置 1 个有效入口时，可直接展示为按钮，例如 `Join Telegram`。
- 当配置多个有效入口时，建议展示为“官方社群”按钮组或图标按钮组。
- “前往仪表盘”继续保留主按钮视觉层级，社群入口使用次级按钮或图标按钮样式。

入口展示条件：

- 入口 `enabled = true`
- 入口 `url` 不为空
- 入口 `url` 为合法安全 URL
- 入口平台类型有效

不满足条件的入口不展示。

### 5.2 支持平台

本期内置以下平台类型：

| 平台类型 | 默认展示名称 | 链接示例 |
| --- | --- | --- |
| `telegram` | Telegram | `https://t.me/example` |
| `whatsapp` | WhatsApp | `https://chat.whatsapp.com/example` |
| `facebook` | Facebook | `https://www.facebook.com/example` |
| `instagram` | Instagram | `https://www.instagram.com/example` |
| `x` | X | `https://x.com/example` |
| `vk` | VK | `https://vk.com/example` |
| `custom` | Custom | `https://example.com/community` |

说明：

- `custom` 用于兼容未来新增平台或自定义社群入口。
- 平台类型用于决定默认图标、默认名称和链接校验提示。
- 展示名称允许管理员覆盖，便于配置不同语言或运营文案。

### 5.3 点击跳转

用户点击任一社群入口后，在新窗口打开后台配置的链接。

前端跳转建议：

```tsx
<a href={item.url} target="_blank" rel="noopener noreferrer">
  {item.label || defaultPlatformLabel}
</a>
```

### 5.4 后台配置模块

后台系统设置页新增“官方社群入口”配置模块。

每个入口配置字段：

| 字段 | 类型 | 默认值 | 必填 | 说明 |
| --- | --- | --- | --- | --- |
| `id` | string | 自动生成 | 是 | 前端列表稳定 key，可使用 uuid 或时间戳字符串 |
| `platform` | string | `telegram` | 是 | 平台类型 |
| `label` | string | 平台默认名称 | 否 | 前台展示名称，空值时使用平台默认名称 |
| `url` | string | 空字符串 | 是 | 社群或社交平台链接 |
| `enabled` | boolean | `true` | 是 | 是否展示该入口 |
| `sort` | number | 自动递增 | 是 | 展示排序，数字越小越靠前 |

后台交互能力：

- 新增入口。
- 编辑入口。
- 删除入口。
- 启用或停用入口。
- 调整入口排序。
- 保存全部入口配置。

### 5.5 配置保存与生效

- 配置保存复用现有系统设置保存机制。
- 保存成功后，前端刷新页面后应读取最新配置。
- 如项目已有运行时配置刷新机制，可沿用现有机制实现实时生效。
- 默认配置为空数组，确保存量部署不展示社群入口。

建议配置项：

| 配置项 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `OfficialSocialLinks` | JSON string | `[]` | 官方社群入口列表 |

建议 JSON 结构：

```json
[
  {
    "id": "telegram",
    "platform": "telegram",
    "label": "Telegram",
    "url": "https://t.me/example",
    "enabled": true,
    "sort": 10
  },
  {
    "id": "whatsapp",
    "platform": "whatsapp",
    "label": "WhatsApp",
    "url": "https://chat.whatsapp.com/example",
    "enabled": true,
    "sort": 20
  }
]
```

### 5.6 链接校验

保存配置时需要校验：

- 启用状态下，`url` 必填。
- `url` 必须是合法 URL。
- 仅允许 `https://` 链接。
- 禁止 `javascript:`、`data:`、`file:` 等非安全协议。
- 同一平台允许配置多个入口，但不允许同一个 URL 重复配置。

建议平台链接格式：

| 平台 | 建议允许域名 |
| --- | --- |
| Telegram | `t.me`、`telegram.me` |
| WhatsApp | `chat.whatsapp.com`、`wa.me` |
| Facebook | `facebook.com`、`www.facebook.com`、`fb.com` |
| Instagram | `instagram.com`、`www.instagram.com` |
| X | `x.com`、`twitter.com`、`www.twitter.com` |
| VK | `vk.com`、`www.vk.com` |
| Custom | 任意合法 `https://` URL |

为减少运营配置阻塞，平台域名校验建议作为弱校验提示；强校验只限制合法 `https://` URL。

### 5.7 国际化

新增前端 i18n key，覆盖默认前端支持语言：`en`、`zh`、`fr`、`ru`、`ja`、`vi`。

建议新增 key：

| Key | 用途 |
| --- | --- |
| `Official Communities` | 前台入口组或后台配置模块标题 |
| `Join Official Community` | 单入口通用按钮文案 |
| `Social Platform` | 后台平台类型字段 |
| `Display Name` | 后台展示名称字段 |
| `Community Link` | 后台链接字段 |
| `Enable This Link` | 后台启用开关 |
| `Add Community Link` | 后台新增入口按钮 |
| `Please enter a valid community link` | 链接校验错误 |

平台名称可直接作为品牌名展示，不强制翻译。

## 6. 交互与视觉要求

### 6.1 桌面端

- 社群入口位于“前往仪表盘”按钮旁边。
- “前往仪表盘”保留主按钮视觉层级。
- 多入口建议使用图标按钮组，鼠标悬停时展示平台名称。
- 如果使用文字按钮，按钮文案不得过长影响主页首屏布局。

### 6.2 移动端

- 入口需要自适应布局。
- 多入口建议使用横向可换行图标按钮组。
- 文案不得溢出、遮挡或换行异常。
- 当屏幕宽度不足时，按钮可纵向排列或折叠为更多菜单。

### 6.3 图标要求

- 平台入口应优先展示平台识别度高的图标。
- 如项目已有图标库，应复用现有图标库。
- `custom` 平台可使用通用链接图标。
- 图标按钮需要提供可访问名称，例如 `aria-label`。

### 6.4 安全要求

- 外链打开必须使用 `target="_blank"` 和 `rel="noopener noreferrer"`。
- 前后端都应过滤非安全协议。
- 前台渲染不得直接插入未经处理的 HTML。

## 7. 后端与配置设计建议

### 7.1 配置读取

前端主页应通过现有系统配置接口读取官方社群入口列表。

如果现有主页配置接口已经返回站点级公开配置，应将 `OfficialSocialLinks` 加入公开配置响应；如果仅后台可见，需要新增或扩展前台可读的公开配置字段。

公开给前台时，仅返回必要字段：

```json
[
  {
    "platform": "telegram",
    "label": "Telegram",
    "url": "https://t.me/example",
    "enabled": true,
    "sort": 10
  }
]
```

### 7.2 配置保存

后台保存配置时：

- 使用现有 option/config 存储机制，不新增独立业务表。
- JSON 序列化和反序列化必须使用项目 `common/json.go` 封装方法。
- 保存前按 `sort` 排序并清理无效项。
- 配置为空数组时，前台不展示任何社群入口。

### 7.3 数据兼容

- 默认值为 `[]`。
- 不依赖数据库特定 JSON 类型，建议以 `TEXT` 字段存储 JSON 字符串。
- 不影响存量部署。

## 8. 验收标准

- 默认配置为空时，主页不展示官方社群入口。
- 后台新增 Telegram 入口、开启并配置合法链接后，主页展示 Telegram 入口。
- 后台新增 WhatsApp、Facebook、Instagram、X、VK 等多个入口后，主页按排序展示多个入口。
- 点击任一入口后，新窗口打开对应配置链接。
- 后台停用某个入口后，主页不再展示该入口。
- 后台删除某个入口后，主页不再展示该入口。
- 启用状态下链接为空，后台保存失败并提示用户。
- 链接非法或非 `https://` 协议时，后台保存失败并提示用户。
- 桌面端和移动端入口布局正常，无文字溢出、遮挡或错位。
- 所有新增前端文案均接入 i18n。
- 不影响现有“前往仪表盘”按钮逻辑。

## 9. 测试用例

| 用例 | 前置条件 | 操作 | 预期结果 |
| --- | --- | --- | --- |
| 默认不展示 | `OfficialSocialLinks=[]` | 打开主页 | 不展示官方社群入口 |
| 新增单个入口 | 后台新增 Telegram，开启并配置合法链接 | 打开主页 | 展示 Telegram 入口 |
| 新增多个入口 | 后台新增 Telegram、WhatsApp、Facebook、Instagram、X、VK | 打开主页 | 按排序展示多个入口 |
| 点击跳转 | 入口已展示 | 点击任一入口 | 新窗口打开对应链接 |
| 停用入口 | 后台停用 WhatsApp | 打开主页 | 不展示 WhatsApp 入口，其他入口正常展示 |
| 删除入口 | 后台删除 Telegram | 打开主页 | 不展示 Telegram 入口 |
| 启用但链接为空 | 后台启用入口，链接为空 | 保存配置 | 保存失败并提示链接必填 |
| 链接非法 | 后台输入非法链接 | 保存配置 | 保存失败并提示链接非法 |
| 非 HTTPS 链接 | 后台输入 `http://example.com` | 保存配置 | 保存失败并提示仅支持 HTTPS |
| 重复 URL | 后台配置两个相同 URL | 保存配置 | 保存失败或提示 URL 重复 |
| 移动端适配 | 使用移动端视口 | 打开主页 | 入口布局正常，无溢出 |

## 10. 风险与注意事项

- 各社交平台链接格式可能变化，强校验不宜过度限制平台域名。
- 部分部署区域可能无法访问部分社交平台，入口仅作为外链，不保证第三方页面可访问。
- 多入口过多会影响主页首屏简洁度，建议后台限制最多配置 6 到 8 个展示入口。
- 后续如需要点击统计，可在本配置结构上增加 `trackingKey` 或通过前端埋点扩展。
