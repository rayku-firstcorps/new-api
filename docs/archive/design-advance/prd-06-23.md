## 2. 背景与问题

当前首页首屏已完成轻量化、文档化的视觉方向，但截图中仍存在三处需要调整的位置：

1. 红框位置位于 Hero 主 CTA 下方，目前展示模型标签，例如 `GPT-5.2`、`Claude Opus 4.7`、`Grok 4.2`、`Gemini 3.1 Pro`。该位置应改为官方社媒图标入口，并读取后台已配置的官方社媒链接。
2. 黄色框位置位于“一个接口，连接你已经在用的 AI 工具”区块下方，目前展示“复制基础地址”和“查看指南”两个按钮。该按钮组在当前页面节奏中造成重复转化，应移除。
3. 首页“开发者文档 / Developer Docs”入口应连接到本项目内置文档页 `/docs`，而不是外部默认文档站或其他 newapi 文档地址。

## 3. 目标

- 将 Hero 红框区域从模型标签切换为官方社媒图标组，增强品牌信任与社区触达。
- 复用后台 `OfficialSocialLinks` 配置，不新增重复配置项。
- 移除统一接入配置区黄色框按钮组，降低页面噪音。
- 首页所有开发者文档入口统一跳转到本项目内部 `/docs`。
- 保持现有首页视觉气质：白底网格、轻量、克制、开发者友好。

## 4. 非目标

- 不新增社媒后台配置模型；本期只复用已有官方社媒链接配置。
- 不重做首页信息架构。
- 不新增社媒点击埋点。
- 不改造 `/docs` 文档页内容。
- 不移除顶部导航中的“文档”入口。

## 7. 功能需求

### 7.1 红框区域改为社媒图标

红框位置指截图中 Hero 主 CTA 下方、原模型标签所在区域。

要求：

- 移除原静态模型标签展示。
- 改为展示后台配置的官方社媒图标组。
- 数据来源为公开状态接口返回的 `official_social_links` 或 `OfficialSocialLinks`。
- 仅展示满足以下条件的社媒项：
  - `enabled = true`
  - `url` 非空
  - `url` 为安全 HTTPS 链接
  - `platform` 为受支持平台
- 展示顺序按 `sort` 升序。
- 无有效社媒链接时，该区域整体隐藏，不回退展示模型标签。
- 点击图标后在新窗口打开对应链接，并使用 `rel="noopener noreferrer"`。

支持平台沿用现有类型：

| platform | 展示名称 | 图标建议 |
| --- | --- | --- |
| `telegram` | Telegram | Telegram 品牌图标 |
| `whatsapp` | WhatsApp | WhatsApp 品牌图标 |
| `facebook` | Facebook | Facebook 品牌图标 |
| `instagram` | Instagram | Instagram 品牌图标 |
| `x` | X | X 品牌图标 |
| `vk` | VK | VK 品牌图标 |
| `custom` | 自定义链接 | 通用链接图标 |

### 7.2 社媒图标视觉与交互

桌面端：

- 图标组位于 Hero CTA 下方，保持与原模型标签相近的垂直间距。
- 使用圆形或轻量圆角图标按钮，尺寸建议 32px 至 36px。
- 图标按钮视觉层级低于主 CTA，不使用大面积实色按钮。
- 每个图标悬停时显示平台名称，可使用浏览器 `title` 或现有 Tooltip 组件。
- 多个图标横向居中排列，间距建议 8px 至 10px。

移动端：

- 图标组保持居中，可换行。
- 不出现横向滚动。
- 触控热区不小于 32px。
- 图标与 Hero CTA 保持清晰间距，避免误触。

可访问性：

- 每个入口必须有可访问名称，例如 `aria-label="Telegram"`。
- 图标不可作为唯一不可识别信息；无障碍名称应读取后台 `label` 或平台默认名称。

### 7.3 黄色框按钮组移除

黄色框位置指截图中统一接入配置区下方的按钮组：

- “复制基础地址”
- “查看指南”

要求：

- 完整移除该按钮组及其占位间距。
- 保留上方工具网格本身。
- 移除后该区块底部留白需自然收口，避免出现异常空洞。
- 不影响其他位置的主 CTA、定价入口和开发者文档入口。
- 不要求删除复制基础地址能力的底层工具函数；本期只从该首页区块移除入口。

### 7.4 Developer Docs 跳转到内置 `/docs`

首页中所有“Developer Docs / 开发者文档”入口必须跳转到本项目内置文档页 `/docs`。

要求：

- Hero 区块中的 `Developer Docs` 按钮跳转 `/docs`。
- Developer Access 区块中的 `Developer Docs` 按钮跳转 `/docs`。
- 首页不应使用外部默认文档站作为 Developer Docs 的跳转目标。
- 首页不应根据 `docs_link` 将 Developer Docs 改为外链。
- 顶部导航“文档”当前已指向 `/docs`，需保持一致。
- 如果其他业务页面仍需要使用后台 `docs_link`，不在本期范围内调整。

## 8. 配置与数据要求

### 8.1 社媒配置

复用现有后台配置项：

| 配置项 | 类型 | 说明 |
| --- | --- | --- |
| `OfficialSocialLinks` | JSON string | 官方社媒链接列表 |

前台公开响应兼容字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `official_social_links` | array | 推荐前台字段 |
| `OfficialSocialLinks` | array | 兼容字段 |

示例：

```json
[
  {
    "id": "telegram",
    "platform": "telegram",
    "label": "Telegram",
    "url": "https://t.me/example",
    "enabled": true,
    "sort": 10
  },
  {
    "id": "x",
    "platform": "x",
    "label": "X",
    "url": "https://x.com/example",
    "enabled": true,
    "sort": 20
  }
]
```

### 8.2 文档路由

首页 Developer Docs 固定使用：

```txt
/docs
```

不再使用：

```txt
https://docs.newapi.pro
```

也不使用后台 `docs_link` 覆盖首页 Developer Docs 入口。

## 9. 页面状态

| 状态 | 预期表现 |
| --- | --- |
| 无任何有效社媒链接 | Hero CTA 下方社媒区域隐藏 |
| 只有 1 个有效社媒链接 | 居中展示 1 个图标按钮 |
| 有 2 至 6 个有效社媒链接 | 居中展示一行图标按钮 |
| 有超过 6 个有效社媒链接 | 按配置排序展示，可换行；建议设计上最多保持首屏不拥挤 |
| 社媒链接配置了非 HTTPS URL | 前台不展示该入口 |
| 社媒链接后台停用 | 前台不展示该入口 |
| 点击 Developer Docs | 当前页内路由进入 `/docs` |

## 10. i18n 要求

- 若新增可见文案，必须接入前端 i18n。
- 平台名称可沿用品牌原名，不强制翻译。
- 图标 Tooltip 或 `aria-label` 可使用后台 `label`；如果为空则使用平台默认名称。
- 本期建议不新增首屏说明文案，优先使用纯图标入口，避免破坏首屏简洁度。

## 11. 设计验收标准

- 红框位置不再出现模型标签。
- 红框位置出现后台配置的官方社媒图标，或在无有效配置时完全隐藏。
- 社媒图标与 Hero CTA 对齐居中，视觉重量低于主 CTA。
- 黄色框按钮组完全消失，不保留空白按钮容器。
- 首页 Developer Docs 跳转 `/docs`，不是外链。
- 桌面端和移动端均无文字溢出、遮挡、错位。
- 首页整体仍保持轻量文档风格，不新增营销化大卡片或大块说明文本。

## 14. 交付清单

- 首页 Hero 红框区域：模型标签替换为社媒图标组。
- 首页统一接入配置区：移除黄色框按钮组。
- 首页 Developer Docs：统一跳转 `/docs`。
- 相关新增或调整文案接入 i18n。
- 桌面端与移动端截图验收。
- 单元测试或组件测试覆盖社媒过滤、排序与文档路由逻辑。

## 15. 风险与注意事项

- 社媒图标过多会影响首屏简洁度，建议运营侧控制在 4 至 6 个以内。
- 首页 Developer Docs 固定 `/docs` 后，后台 `docs_link` 对首页不再生效；如有其他页面依赖该配置，应保持原逻辑不变。
- 社媒 URL 必须继续做安全过滤，避免将不安全协议渲染到前台。
- 移除黄色按钮后，应检查该区块与下一段内容之间的垂直节奏，避免页面显得断裂。
